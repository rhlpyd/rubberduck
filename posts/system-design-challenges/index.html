System Design Challenges for Principal Engineers

A curated list of Go-based system design problems to master distributed systems at scale

Why These Problems Matter

At principal and distinguished engineer levels at companies like Google and Meta, you’re expected to design systems that handle billions of users, petabytes of data, and maintain 99.99% uptime. These problems simulate real-world challenges you’ll face when architecting large-scale distributed systems.

The Challenge List

1. Distributed Rate Limiter Service

Complexity: High
Key Skills: Distributed algorithms, Redis, consistent hashing
Scale Target: Millions of requests/second across multiple data centers

Build a rate limiting service that can handle different algorithms (token bucket, sliding window, leaky bucket) while maintaining consistency across a distributed system. Focus on minimizing latency and handling network partitions gracefully.

2. Distributed Cache System

Complexity: High
Key Skills: Consistent hashing, replication, failover
Scale Target: Redis-like performance with automatic scaling

Create a distributed cache that can partition data across nodes, handle node failures, and maintain data consistency. Implement features like TTL, LRU eviction, and cluster management.

3. Message Queue System

Complexity: Very High
Key Skills: Event streaming, partitioning, consumer groups
Scale Target: Kafka-scale throughput with ordering guarantees

Design a distributed message broker that handles topic partitioning, consumer groups, and different delivery semantics (at-least-once, exactly-once). Focus on durability and horizontal scaling.

4. Time Series Database

Complexity: High
Key Skills: Data compression, indexing, aggregation
Scale Target: InfluxDB-like metrics storage

Build a system optimized for time-series data with efficient compression, downsampling, and retention policies. Handle high write throughput while maintaining query performance.

5. Search Engine

Complexity: Very High
Key Skills: Inverted indexes, relevance scoring, distributed search
Scale Target: Elasticsearch-scale with real-time indexing

Create a distributed search system with inverted indexes, relevance scoring, and faceted search. Implement real-time indexing and query optimization across multiple nodes.

6. Event Sourcing System

Complexity: High
Key Skills: CQRS, event replay, distributed transactions
Scale Target: Banking-grade consistency and auditability

Design an event store with CQRS pattern, handling event replay, snapshots, and projection rebuilding. Implement saga patterns for distributed transactions.

7. URL Shortener (Advanced)

Complexity: Medium-High
Key Skills: Global distribution, analytics, custom domains
Scale Target: 100M URLs/day with global CDN

Build a URL shortener that handles massive scale with custom base62 encoding, real-time analytics, A/B testing, and custom domain support across multiple regions.

8. Chat System

Complexity: Very High
Key Skills: WebSocket scaling, message delivery, encryption
Scale Target: WhatsApp-scale messaging

Create a real-time messaging system with WebSocket connections, message delivery guarantees, read receipts, group chats, and end-to-end encryption.

9. Content Delivery Network

Complexity: Very High
Key Skills: Edge computing, caching strategies, load balancing
Scale Target: Global CDN with intelligent routing

Build edge servers with intelligent caching, origin pull, cache invalidation, and geographic routing. Add features like image optimization and dynamic content acceleration.

Advanced Challenge Problems

Additional system design problems for specialized domains and advanced scenarios

Database Systems

10. Distributed SQL Database

Complexity: Very High
Key Skills: ACID transactions, consensus protocols, query optimization
Scale Target: CockroachDB-like global consistency

Build a distributed SQL database that maintains ACID properties across multiple nodes. Implement distributed transactions, query planning, and automatic rebalancing.

11. NoSQL Document Store

Complexity: High
Key Skills: Document indexing, flexible schemas, horizontal scaling
Scale Target: MongoDB-like document storage with sharding

Create a document database with flexible schemas, secondary indexes, and automatic sharding. Handle complex queries and aggregation pipelines.

12. Graph Database

Complexity: Very High
Key Skills: Graph algorithms, distributed graph traversal, partitioning
Scale Target: Neo4j-like graph queries at scale

Design a distributed graph database that can handle complex graph traversals and pattern matching across partitioned data.

13. Database Replication Coordinator

Complexity: High
Key Skills: Master-slave replication, conflict resolution, failover
Scale Target: MySQL-like replication with automatic failover

Build a system that manages database replication, handles split-brain scenarios, and provides automatic failover capabilities.

Real-Time Systems

14. Live Video Streaming Platform

Complexity: Very High
Key Skills: Video encoding, CDN integration, real-time protocols
Scale Target: Twitch-scale live streaming

Create a platform that handles live video ingestion, transcoding, and distribution to millions of concurrent viewers with low latency.

15. Real-Time Collaboration System

Complexity: Very High
Key Skills: Operational transforms, conflict resolution, WebSocket scaling
Scale Target: Google Docs-like collaborative editing

Build a system that allows multiple users to edit documents simultaneously with real-time synchronization and conflict resolution.

16. Gaming Leaderboard

Complexity: Medium-High
Key Skills: Real-time ranking, sorted sets, cache invalidation
Scale Target: Global leaderboards with millions of players

Design a leaderboard system that can handle millions of score updates and provide real-time rankings across different time windows.

17. Live Sports Scoring System

Complexity: High
Key Skills: Event streaming, real-time updates, fan-out patterns
Scale Target: ESPN-like real-time sports data

Create a system that ingests live sports data and distributes updates to millions of users with sub-second latency.

Build a payment system that handles transactions securely, maintains financial compliance, and provides fraud detection capabilities.

Scale Target: Microsecond latency for high-frequency trading

Design a trading engine that can process orders with microsecond latency while maintaining fairness and regulatory compliance.

20. Blockchain System

Scale Target: Ethereum-like distributed ledger

Create a blockchain system with smart contracts, consensus mechanisms, and decentralized validation.

21. Banking Transaction Processor

Complexity: Very High

Scale Target: Bank-grade transaction processing

Build a system that processes banking transactions with strict consistency, audit trails, and regulatory compliance.

Design a platform that serves ML models at scale with versioning, canary deployments, and performance monitoring.

Scale Target: Feast-like feature management

Create a centralized feature store that manages feature engineering pipelines and serves features for ML training and inference.

24. A/B Testing Platform

Complexity: Medium-High
Key Skills: Statistical analysis, experiment design, traffic splitting
Scale Target: Optimizely-like experimentation platform

Build a platform that manages A/B tests with proper statistical analysis and traffic allocation across multiple experiments.

25. Recommendation Engine

Complexity: Very High
Key Skills: Collaborative filtering, real-time inference, personalization
Scale Target: Netflix-like recommendation system

Design a recommendation system that provides personalized content suggestions using collaborative filtering and content-based approaches.

Monitoring & Observability

26. Distributed Logging System

Complexity: High
Key Skills: Log aggregation, indexing, search optimization
Scale Target: ELK stack-like log processing

Create a system that collects, indexes, and searches logs from distributed applications with real-time alerting capabilities.

27. Metrics Collection Platform

Complexity: High
Key Skills: Time-series data, aggregation, alerting
Scale Target: Datadog-like metrics platform

Build a metrics collection system that handles high-cardinality data with efficient storage and real-time alerting.

28. Application Performance Monitoring

Complexity: High
Key Skills: Profiling, performance analysis, anomaly detection
Scale Target: New Relic-like APM solution

Design an APM system that monitors application performance, detects anomalies, and provides root cause analysis.

29. Distributed Tracing System

Complexity: High
Key Skills: Trace correlation, sampling strategies, visualization
Scale Target: Jaeger-like distributed tracing

Create a tracing system that tracks requests across microservices with efficient sampling and trace correlation.

Security & Identity

30. OAuth/SSO Provider

Complexity: High
Key Skills: Authentication protocols, security standards, token management
Scale Target: Auth0-like identity platform

Build an identity provider that supports OAuth, SAML, and other authentication protocols with enterprise-grade security.

31. API Gateway

Complexity: High
Key Skills: Request routing, authentication, rate limiting
Scale Target: Kong-like API management

Design an API gateway that handles authentication, rate limiting, request transformation, and traffic routing.

32. Secrets Management System

Complexity: High
Key Skills: Encryption, access control, audit logging
Scale Target: HashiCorp Vault-like secrets management

Create a system for securely storing and managing secrets with fine-grained access control and audit capabilities.

33. Fraud Detection System

Complexity: Very High
Key Skills: Machine learning, real-time scoring, rule engines
Scale Target: PayPal-like fraud prevention

Build a real-time fraud detection system that uses ML models and rule engines to identify suspicious transactions.

Technical Focus Areas

Core Distributed Systems Concepts

  • Consistency models (eventual, strong, causal)
  • Partition tolerance and CAP theorem
  • Consensus algorithms (Raft, PBFT)
  • Load balancing and service discovery

Go-Specific Skills

  • Goroutines and channel patterns
  • Memory management and GC optimization
  • Profiling and performance tuning
  • Context handling and cancellation

Operational Excellence

  • Monitoring and alerting (Prometheus, Grafana)
  • Distributed tracing (Jaeger, OpenTelemetry)
  • Circuit breakers and bulkhead patterns
  • Chaos engineering and fault injection

Infrastructure & Deployment

  • Kubernetes and service mesh
  • Docker containerization
  • Blue-green and canary deployments
  • Infrastructure as code (Terraform)

Getting Started

Recommended Learning Path

Phase 1: Core Distributed Systems (Problems 1-9)

  1. Start with Rate Limiter - It’s foundational and teaches core distributed systems concepts
  2. Progress to Distributed Cache - Builds on rate limiter concepts with data persistence
  3. Tackle Message Queue - Introduces event-driven architecture patterns
  4. Choose your specialty - Pick remaining core problems based on your interests

Phase 2: Specialized Domains (Problems 10-33) After mastering the core challenges, choose problems based on your career focus:

  • Backend Infrastructure: Database systems, monitoring & observability
  • Real-Time Systems: Live streaming, collaboration, gaming
  • Financial Technology: Payment processing, trading engines
  • Machine Learning: Model serving, feature stores, recommendations
  • Security: Identity management, fraud detection, secrets management

Success Criteria

For each system, aim to achieve:

  • Production-ready code with proper error handling
  • Comprehensive testing including chaos engineering
  • Detailed documentation with architecture diagrams
  • Performance benchmarks with load testing results
  • Operational runbooks for deployment and monitoring

Next Steps

The complete challenge set now includes 33 problems spanning core distributed systems and specialized domains. Here’s how to approach them:

Timeline: Each problem should take 2-4 weeks to implement properly. Focus on one at a time, and build each system to production standards.

Progression: Start with the core 9 problems (1-9) before moving to specialized challenges (10-33). The core problems provide foundational knowledge needed for the advanced ones.

Goal: The objective isn’t just to make systems work, but to make them work reliably at scale with proper monitoring, testing, and operational procedures.

Career Focus: After completing the core challenges, choose specialized problems that align with your career goals - whether that’s infrastructure, fintech, ML, security, or real-time systems.

Ready to start your journey to principal engineer level? Pick your first challenge and begin building!
